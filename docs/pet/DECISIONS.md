# 技术决策记录（ADR）

每条记录：**背景 → 选项 → 决定 → 理由 → 代价**。
只写真正做过取舍的地方，不写"显然如此"的事。

---

## ADR-001 固件基座用 xiaozhi-esp32，不自研

**背景**：要一台会说话、有表情的桌面设备。

**选项**
1. 从零写固件
2. 刷第三方系统（MicroPython / LVGL demo / 别人的固件）
3. 基于 xiaozhi-esp32 改显示层

**决定**：3。

**理由**：语音链路（唤醒词、AEC、ASR、LLM、TTS、断线重连、配网、OTA）是整件事里
最难也最没差异化的部分，上游已经成熟；这块板的板型支持也已经存在。我们真正要做的
只有"脸和性格"。

**代价**：仓库大（171 个变体）、构建慢、依赖多。用独立仓库 + 单板型变体隔离。

---

## ADR-002 表情用程序化渲染，不用 GIF / EAF

**背景**：原方案是 13 个 160×160 GIF，占 6MB 资源分区。

**选项**
1. 继续堆 GIF
2. 用 EAF（esp_emote_gfx）烘帧
3. 本地实时渲染

**决定**：3，EAF 只作为未来的特效补充。

**理由**
- 体积：一个 GIF ≈ 450KB，13 个 ≈ 6MB；程序化渲染**不占资源分区**，只占一个
  240×240×2 = 115KB 的帧缓冲。
- 反应：GIF 是固定循环，没法随声音、重力、时间实时变化。
- 帧率：EAF 解决了 GIF 解码开销，但没解决"素材是死的"。

**代价**：美术上限不如手绘动画；复杂特效（粒子、高光）要靠代码画。

## ADR-003 行为优先级用"覆盖式阶梯"，不用显式状态机

**背景**：触摸、眩晕、情绪、说话、聆听、瞌睡、待机七个来源同时想控制脸。

**选项**
1. 显式 FSM（状态 + 转移表）
2. 各系统独立更新，最后写入
3. 每帧从底向上覆盖的优先级阶梯

**决定**：3。

**理由**：这些行为本质是**叠加**不是**互斥**（说话时也可以被摸）。FSM 会状态爆炸
（7 个来源的笛卡尔积），而阶梯只需要维护一个顺序，新增行为就是"插一层"。

**代价**：顺序成为隐式契约，必须写在代码顶部注释里（已写在 `Tick()` 里）。

---

## ADR-004 IMU / RTC 共用板级 I2C

**背景**：触摸、AXP2101、ES8311/ES7210、QMI8658、PCF85063 都在同一条 I2C 上。

**选项**
1. 每条外设单独开总线
2. 复用板子已建好的总线

**决定**：2。板子把 `i2c_bus_` 通过 `SetSharedI2cBus()` 交给显示层。

**理由**：I2C 是总线不是点对点，重复 `i2c_new_master_bus` 会失败或抢引脚。

**代价**：设备地址必须准确（IMU **0x6B**、RTC **0x51**），任一处写错表现为
"设备不存在"；读失败必须降级而不是崩。

## ADR-005 音频电平只读旁路，不改数据流

**背景**：要让脸对"你说话"和"它说话"有反应。

**选项**
1. 在音频管线中间插入处理
2. 单独开一路 I2S 抓数据
3. 在管线出口挂只读电平表

**决定**：3（输入在 `ReadAudioData()`，输出在 `OutputData()` 前）。

**理由**
- 插入处理会影响 AEC 的参考信号，回声消除会把提示音当成用户说话。
- 单独开 I2S 会抢硬件通道。
- 只读 RMS 只增加一次遍历，不改变任何样本。

**代价**：只能拿到"整体响度"，做不了声源定位。

## ADR-006 刷机用 watchdog reset

**背景**：每次 `idf.py flash` 后屏幕不亮、串口消失，必须拔插 USB。

**选项**
1. hard reset（默认）
2. no-reset + 手动按键
3. watchdog reset

**决定**：3，封装成 `scripts/pet/flash.ps1`。

**理由**：这块板的 USB 是芯片原生 USB，hard reset 后 USB 枚举和 AXP2101 的屏幕供电
不会重新初始化；watchdog reset 会走完整的复位流程。实测刷完端口仍在、屏幕正常。

**代价**：不能用 `idf.py flash`，团队协作时要说明。

## ADR-007 性能优化顺序：脏区 → 行缓冲 → 查表 → 降分辨率

**背景**：300×300 画布单帧 29–34ms，30fps 只剩几毫秒余量。

**决定与效果**

| 手段 | 效果 |
|---|---|
| 只重绘上一帧的脏区 | 省一次全画布清屏 |
| 行缓冲 + 整行 `memcpy` 到 PSRAM | 避免逐像素写 PSRAM |
| 65 档颜色查表 | 每像素 3 次 float→int 变 1 次 |
| 画布 300→240、半径 110→88 | 像素数 −36%，**最大贡献** |

**结果**：29–34ms → **16–20ms**。

**没做的**：定点数（可再降到 10–12ms），当前余量够用，不值得增加复杂度。

## ADR-008 OTA 自建，且地址运行时可变

**背景**：不能每次都插线；官方 OTA 会覆盖我们的自定义固件。

**选项**
1. 小智官方 OTA 通道
2. 自建 HTTP 服务

**决定**：2，并且地址存 NVS（`wifi/ota_url`），提供 `self.system.set_ota_url` 工具。

**理由**
- 官方通道推的是官方固件，会把脸换掉。
- 自建只需要一个静态文件服务器；设备本来就支持 `ota_url` 配置。
- 双槽结构（`ota_0` @0x20000、`ota_1` @0x410000、`otadata` @0xd000）本来就存在，
  **不需要重新分区**，升级失败自动回退。

**代价**：需要一个能访问的服务器；清单必须支持 **POST**（设备用 POST 请求），
Python 自带 `http.server` 不行，参考 `local-only/ota/server.py`。

## ADR-009 崩溃循环自愈（安全模式）

**背景**：一次错误改动让 SNTP 在 lwIP 就绪前初始化，`tcpip_callback` 断言 → 复位
→ 再断言，设备每 2 秒重启，屏幕看起来在闪。

**决定**：NVS 启动计数；连续 3 次没撑过 30 秒 → 安全模式（跳过 SNTP 等可选功能）；
稳定 30 秒清零。

**理由**：固件在现场时没人能插线，必须自己能恢复。可选功能失败不应该拖垮整个设备。

**代价**：多一次 NVS 读写；安全模式期间没有 NTP（时间靠 RTC 走时）。

## ADR-010 时间用 RTC + SNTP，记忆用"一周第几分钟"

**背景**：昼夜节律需要绝对时间；"多久没见"需要跨重启的相对时间。

**决定**
- 绝对时间：开机联网后 SNTP 对时，**写回 PCF85063**，断电靠纽扣电池。
- 相对记忆：NVS 存 `wow`（weekday×1440 + hour×60 + min），差值对 10080 取模。

**理由**：出厂 RTC 时间是错的（实测差 4 小时、星期错），不能直接用；而"过了多久"
只需两个时间点在同一个周期坐标系里相减，避免处理日期、时区、闰年。

**代价**：超过一周的离开会被算成"一周内"；没电池时每次开机都要重新 NTP。

## ADR-011 明确不做的事

| 不做 | 原因 |
|---|---|
| 刷第三方系统 | 屏幕/触摸/音频驱动全要重写，且丢掉语音能力 |
| 视频播放 | 这块屏是给脸用的，不是给内容用的 |
| 音频混音（点击音效混进 TTS） | 会污染 AEC 参考信号，30ms 音效不值得 |
| 通用 App 平台 | 设备的价值是"一个角色"，不是"一台小手机" |
| 用 GIF/EAF 承载表情 | 见 ADR-002 |

## 附：一次真实故障的完整链路（ADR-009 的由来）

```
改了什么：加 SNTP 对时
怎么坏的：在显示层 Tick（开机 ~0.7s）里调用 esp_sntp_init()
         → lwIP tcpip 线程尚未创建 → tcpip_callback 断言 → 复位
表象：屏幕每 2 秒闪一次，串口反复打印同一段启动日志
定位：串口里捕获到 assert failed: tcpip_callback (Invalid mbox)
修复：三重门控——启动 25s 后 + 网卡已 up + 设备处于 idle
加固：启动计数 → 安全模式，避免下次再死循环
```

这条链路值得记住：**任何"联网/时间/云"相关的初始化，都必须等网络栈就绪**。
