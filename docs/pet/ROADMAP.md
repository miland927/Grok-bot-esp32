# 开发路线图（任务书）

每个任务按同一格式记录：**目标 → 做法 → 关键参数 → 验收 → 证据 → 状态**。
状态只有三种：✅ 已完成并验证 / ⚠️ 已接入但未验证 / ⏳ 未做。

---

## 阶段一：让它"活着"

### 1.1 麦克风电平驱动表情 ✅

- **目标**：它得知道你什么时候在说话，并且把注意力转过去。
- **做法**：在 `AudioService::ReadAudioData()` 的出口挂一个只读回调
  `audio_input_level_update()`，计算 RMS 并做包络；显示层通过
  `audio_input_level()` 取用。**不改变音频数据流**，AEC 与唤醒词不受影响。
- **关键参数**：起音 0.65 / 释放 0.08；说话阈值 `> 0.02`；最多放大 +25%。
- **验收**：说话时眼睛随音量变化；静音时无抖动。
- **证据**：串口 `PetDisplay: voice 0.063`；TTS 路径 `speak 0.244`。

### 1.2 IMU 反应 ✅

- **目标**：拿起来、摇晃、倾斜要有反应，而且三种要能区分。
- **做法**：`pet_imu.c` 用 `waveshare/qmi8658` 驱动，挂在**板级共享 I2C** 上
  （板子把 `i2c_bus_` 通过 `SetSharedI2cBus()` 交给显示层）。
- **关键参数**
  - 地址 **0x6B**（不是 0x6A）；量程 ±8g / ±512dps；采样 500Hz，显示层每 66ms 读一次
  - 拿起：`acc_dev > 0.45g`
  - 眩晕：**连续 4 帧 > 600 dps**（约 250ms 持续甩动）；随手倾斜不会触发
  - 倾斜：增益 1.0，眼睛位移系数 0.34
  - 倾斜只在 `gyro < 120 dps` 时跟随重力——旋转中加速度计噪声会让眼睛左右甩
- **验收**：拿起→惊讶；猛摇→眩晕；慢慢倾斜→视线平滑跟随；静置无误触发。
- **证据**：`PetImu: ready at 0x6b`；`imu surprise dev=1.00`。
- **踩坑**：地址写成 0x6A 时 `whoami` 读不到；180dps 阈值会让普通倾斜误触发眩晕。

### 1.3 手势 ✅

- **目标**：单击、双击、长按、拖动各有不同反应。
- **做法**：在 canvas 上注册 `PRESSED / PRESSING / RELEASED / PRESS_LOST`
  四个事件；用时间差区分手势。
- **关键参数**：长按 `> 700ms`；双击窗口 `< 350ms`；拖动在按下 200ms 后开始跟随；
  双击触发 `spin_v_ = 15 rad/s` 的旋转并衰减。
- **验收**：四种手势互不干扰。
- **证据**：`pat at x,y` / `double tap -> spin` / `long press -> sleepy`。
- **踩坑**：`lv_indev_active()` 只在事件回调里有值，定时器里恒为 NULL——
  触摸检测必须走事件，不能轮询。

### 1.4 昼夜节律 ✅

- **目标**：晚上会困，白天精神，且跨重启有效。
- **做法**：`pet_rtc.c` 读 PCF85063（I2C **0x51**），做 BCD 解码；
  开机联网后 SNTP 对时并**写回 RTC**，断电由纽扣电池走时。
- **关键参数**：夜间 23:00–07:00；夜间眼睛 ×0.8、视线下垂 +0.08、呼吸 0.8 rad/s；
  说话/聆听时抑制。
- **验收**：时间正确、星期正确、夜间生效。
- **证据**：`sntp synced 2026-11-03 00:08:07 -> rtc`、`rtc 00:08 wd=2 night=1`。
- **踩坑**：RTC 出厂时间不准（实测差 4 小时、星期错），必须先 NTP 校准再用。

### 1.5 点击音效 ✅（听感未确认）

- **目标**：点击有反馈音，但绝不打断对话。
- **做法**：复用固件已有的 `Lang::Sounds::OGG_POPUP`，**只在
  `kDeviceStateIdle`** 时调用 `Application::PlaySound()`。
- **验收**：待机点击有声；对话中点击无声。
- **状态**：代码已刷入，声音未被人工确认。
- **为什么不做混音**：会污染 AEC 参考信号，一个 30ms 音效不值得。

## 阶段二：性格

### 2.1 状态机（优先级阶梯）✅

- **目标**：把散落的 `if` 收敛成可预测的规则。
- **做法**：每帧从底向上覆盖计算目标，顺序即优先级：

  ```
  1 触摸  >  2 眩晕  >  3 情绪  >  4 说话  >  5 聆听  >  6 瞌睡  >  7 待机
  ```

- **验收**：任意组合下行为不打架。
- **证据**：重写后 `speak 0.237` 等行为无回归，帧率不变。

### 2.2 微动作库 ✅

- **目标**：静置时看起来"没死"。
- **做法**：12–40 秒随机挑一个动作：张望 / 连眨两下 / 小跳 / 叹气。
- **验收**：日志能看到动作轮换。
- **证据**：`idle hop`、`idle look -0.90 0.10`、`idle double blink`。

### 2.3 说话时联动 ✅

- **目标**：它说话时脸要动。
- **做法**：在播放路径 `codec_->OutputData()` 前挂只读电平表
  `audio_output_level_update()`，包络起音 0.8 / 释放 0.2。
- **验收**：眼睛随 TTS 起伏；说话期间不进入瞌睡。
- **证据**：`speak 0.244`。

### 2.4 MCP 表情工具 ✅

- **目标**：让模型能主动演，而不是被动映射。
- **做法**：`mcp_server.cc` 注册三个工具：

  | 工具 | 参数 |
  |---|---|
  | `self.pet.set_mood` | mood 字符串（neutral/happy/sad/angry/surprised/thinking/sleepy/listening） |
  | `self.pet.look_at` | x, y（−100..100） |
  | `self.pet.status` | 无参数，返回 mood/battery/time/drowsy/night/safe |

- **验收**：工具注册成功，模型可按需调用。
- **证据**：`MCP: Add tool: self.pet.set_mood` 等三条。

### 2.5 记忆钩子 ✅

- **目标**：它记得你来过。
- **做法**：NVS 存"最后一次互动"（`mow` = 一周第几分钟）；120 秒无互动打瞌睡；
  被碰时"惊醒"（惊讶 + 跳）；超过 6 小时没见 → "久别重逢"。
- **关键参数**：瞌睡 120s；惊醒动作 0.9s；重逢阈值 360min；NVS 写入节流 5min。
- **验收**：日志有 `drowsy (idle)` / `wake startle` / `welcome back after N min`。
- **证据**：`drowsy (idle)` 已验证；惊醒与重逢需要触摸。

## 阶段三：稳定与产品化

### 3.1 刷机不再掉线 ✅

- **问题**：`idf.py flash` 用 hard reset，这块板的 USB 枚举和屏幕供电不会重新初始化，
  表现为刷完黑屏、串口消失，必须拔插。
- **做法**：改用 `--after watchdog-reset`，封装成 `scripts/pet/flash.ps1`。
- **证据**：刷完 10 秒后 `USB 串行设备 (COM3) OK`，日志正常到 idle。

### 3.2 OTA ✅

- **做法**：自建 HTTP 服务（支持 POST 清单 + Range 下载），设备从
  `CONFIG_OTA_URL` 或 NVS `wifi/ota_url` 取地址；清单格式：

  ```json
  {"firmware":{"version":"1.0.1","url":"http://host:8000/1.0.1.bin"}}
  ```

- **验收**：写入备用槽、重启后版本变化。
- **证据**：`Writing to partition ota_1 at offset 0x410000` → 进度 2%…100% →
  `App version: 1.0.1` → `Current is the latest version`。
- **踩坑**
  - 设备用 **POST** 请求清单，Python 自带 `http.server` 不支持 → 501
  - 检查失败**不能阻塞启动**：这个函数跑在协议创建之前，重试 10 次会让设备
    好几分钟无法对话（现象：唤醒无反应，日志 `Protocol not initialized`）。
    现在只试一次，失败继续启动；默认地址指向 `127.0.0.1:9` 立即失败，
    不拖慢开机；真正升级时用 `self.system.set_ota_url` 改地址。
- **回滚**：只写备用槽，校验失败自动回退，不会砖。

### 3.3 电源 ✅（无电池，未触发）

- **做法**：每 3 秒读 AXP2101；`level < 20% && !charging` → 眼睛 ×0.6、呼吸变慢；
  `level <= 0` 视为无电池，安全跳过。
- **证据**：`battery -1% charging=0`（无电池设备）。
- **未验证**：低电视觉效果需要有电池并放电。

### 3.4 性能优化 ✅

- **做法**：只重绘脏区 + 行缓冲（内部 RAM 拼好后整行 `memcpy`）+ 65 档颜色查表 +
  画布 300→240。
- **结果**：单帧 **29–34ms → 16–20ms**（30fps 下余量 13–17ms）。
- **证据**：`render 18096 us`。
- **下一步**：定点数可再降到 10–12ms，当前不必要。

### 3.5 外壳与结构 ⏳

- **内容**：麦克风开孔、散热、屏幕贴合，不在代码范围。
