# 本机工作台与统一执行器 v0.1

## 启动

在仓库根目录执行：

```sh
python scripts/whale/manager.py
```

打开 http://127.0.0.1:8765 。使用现有Python标准库；视频转换按需调用已安装的FFmpeg/FFprobe，不自动安装SDK或工具。

服务只监听127.0.0.1；校验Host、同源请求、随机请求令牌和素材访问Cookie。页面不加载外部脚本或字体。上传、草稿、转换缓存、候选、日志都在local-only/manager，不进入Git。

## 已实现

- 设备与项目页：目标板、Git分支/提交、工程资源包占用；实际设备状态和指标保持未读取。
- 动作库：当前10种素材动态预览；导入160×160 GIF，或把15秒以内VP9 WebM转换到160px/8fps/64色；以输入哈希、固定参数与FFmpeg版本缓存结果。
- 支持替换现有动作媒体、规则草稿、撤销草稿；不修改原工程素材和资源包。
- 候选打包：校验结构、哈希、10%余量、字体/模型保持不变；结果可重复生成，未变草稿不触发资源传输。
- 新菜单或规则仍需动态固件引擎；候选会明确标识，未开放设备安装接口。
- 主机差异ZIP只打包变化媒体和清单，明确NOT-INSTALLABLE，不冒充设备端增量更新。
- 任务记录：阶段开始/结束、耗时、返回码、完整日志；成功摘要至多20行，失败80行，每行最多500字符。
- 取消/超时回收该任务的子进程；跨进程工作树锁；OS会在进程退出后释放锁。
- 实验预算库按稳定实验ID持久计数，默认最多2次自动写入预留；当前尚未接入真实写入执行器。
- 已核验身份的设备锁接口可跨工作树共用，拒绝用COM3等端口名充当设备身份。

## 统一命令

```sh
python scripts/whale/workflow.py check
python scripts/whale/workflow.py assets
python scripts/whale/workflow.py test
python scripts/whale/workflow.py package
python scripts/whale/workflow.py list
```

脚本等待完成，只返回一次摘要；完整日志在任务JSON指向的local-only目录。检查会明确缺少SDK或v7配置，不把资料当实机检测。

build只复用已激活的ESP-IDF，不自动安装。已知Windows中文工程路径不适合现有构建环境，会阻止该任务并要求对齐英文路径工作树；不自动把当前源码覆盖到另一个目录。

## 必须区分的结果

1. 本轮主机端界面与工具测试通过，不等于设备更新通过。
2. 新增任意动作的“零编译”目标仍需设备端动态注册表集成。本分支不改固件，因此尚未解决动态菜单激活。
3. 资源候选只在电脑生成，当前仍为整个assets.bin；真正按文件更新、断电原子提交和回退尚未集成。
4. CPU/PSRAM/FPS等实时指标尚未接入，页面明确显示未测。任务耗时是主机阶段时长，不是账单或模型Token统计。
5. 新执行器的锁和预算不会自动约束旧私有脚本，不声称已实现所有路径的全局设备互斥。
