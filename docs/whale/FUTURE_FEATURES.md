## A. HEI_MAO_POD2：界面与系统交互参考

来源：https://github.com/Heimao35/HEI_MAO_POD2
核对版本：b8d6b3e4bafa4ad4043faa9252de84a611a9f3e3。

### 已确认是什么

这是一套基于 ESP-IDF / LVGL 的播放器及触摸界面固件，含启动页面、锁屏、页面管理、设置、时钟、音乐及电子书等模块，不只是开机动画；也不意味着桌面操作系统或通用应用运行环境。源码 README 当前几乎为空，判断依据是具体配置和源文件。

- `sdkconfig.defaults` 的目标为 ESP32-P4，默认32MB Flash、外部PSRAM，配置注释对应ESP-IDF 5.5.1。
- `main/main.c` 使用 MIPI DSI 和 CO5300 屏幕接口；`ui_common.h` 定义460×460。
- `ui_manager.c` 使用 LVGL 动画实现页面滑动；`ui_boot.c` 提供启动进度页面。
- `ui_video_player.c` 当前只是视频入口的占位页面，注释说明 MJPEG 解码尚待接入，不能把整个仓库描述成完整视频播放器。
- 未在仓库根目录看到项目主许可证；其中 minimp3 的独立许可不能替代整个项目的授权。现阶段记录来源并研究交互，复用源码或素材前先核实许可。

当前鲸鱼娘设备是 ESP32-S3、SH8601 四线屏、410×502，与 P4 / MIPI 平台不同，不能直接刷其整包或假定具有同样流畅度。应在现有小智工程内逐项适配，不覆盖语音链路、既有板级驱动和已保留分区。

### 计划与通过条件

1. **UI-0：选定参考交互。** 列出要借鉴的开机进度、锁屏/时钟、滑动页面、快捷设置；区分实际已实现的功能和占位入口，明确与鲸鱼娘触摸、文本滚动的手势边界。
2. **UI-1：单页面原型。** 优先做轻量开机/加载反馈及一个设置页面，按410×502重新布局。保留用户已认可的1.2倍人物比例；页面切换期间仍及时响应语音。
3. **UI-2：滑动与返回。** 在语音/动画运行时测试边缘滑动、取消手势、快速往返和回到角色主界面；不要求照搬P4专用显示加速或MIPI驱动。
4. **UI-3：资源与体验验收。** 基线/新UI同条件记录响应、帧耗时、内部SRAM、PSRAM、最大可分配块和音频表现。至少50次页面切换、20轮语音、1小时混合运行，无崩溃、错误手势、持续内存下降或新增明显断音。
5. **UI-4：再选择附加页面。** 音乐、电子书、图片等分别评估输入、存储及音频资源冲突；不因为参考项目存在这些模块就默认全部纳入本次交付。

## B. ESP-CSI：Wi-Fi 活动感知与角色联动

官方仓库：https://github.com/espressif/esp-csi
核对版本：8633d67152db2808f141cc1595970aa9cf406045。
现有底层框架：https://github.com/espressif/esp-idf 。当前项目已使用ESP-IDF v6.1，不需要为了“增加感知”再叠加一套系统。

### 已确认的可行入口与边界

官方文档明确列出 ESP32-S3 支持 CSI。`csi_recv_router` 演示单个ESP32通过向路由器发Ping获取返回数据的CSI；`wifi_sensing_demo` 演示基于 esp_wifi_sensing 的活动/存在感知和现场调参。路由器、环境、天线方向和算法会影响结果。

CSI反映无线信道变化，不直接等于可靠的人体判断。首阶段目标是“附近活动变化”的原型；静止人体存在、动作类别、人数、身份或姿态不作为默认能力。必要时评估增加第二块ESP32作为受控发送端，先说明实测收益再决定硬件。

### 计划与通过条件

1. **CSI-0：兼容性和预算。** 核对ESP-IDF v6.1及目标组件的实际兼容性；测当前固件空闲、对话、动画和Wi-Fi重连时的内部SRAM、PSRAM、最大空闲块与CPU开销，确定有界缓存和采样策略。
2. **CSI-1：独立采集原型。** 优先在独立实验工程/备用板上跑官方基础采集，保存可重放的非凭据数据。若需使用当前唯一设备，先保留当前可用镜像并采用明确的备份/恢复方案；不直接运行通用示例flash覆盖现有factory分区。
3. **CSI-2：现场校准。** 采集空房、有人走动、坐着不动、风扇、宠物/门窗等干扰，分别评估活动和静态存在，确定阈值、迟滞、去抖及冷却。做不到可靠静态存在时，明确仅交付活动检测。
4. **CSI-3：与小智共存。** 使用有界队列和可配置采样率；CSI接收回调内不做重计算或显示。CPU和Wi-Fi负载变化不能明显破坏语音；断网/感知异常时应能关闭感知并保留主功能。
5. **CSI-4：角色联动。** 把已校准的活动/存在事件接到欢迎、醒来、无人空闲等候选动作；加入冷却，避免反复切换或误触发后持续说话。感知不作为安防、身份或医疗判断。
6. **CSI-5：验收。** 暂定实验目标：空房30分钟误联动不超过1次；20次标准走动至少18次检出，同时记录延迟和测试距离。这是待现场验证的目标，不是性能承诺。再做至少20轮语音、3次断网恢复、2小时联合运行；记录误报、漏报、内存与音频问题。未达标则保留实验状态，不能标为可靠人体存在检测。

## C. 容量问题：电脑磁盘与开发板分开看

用户截图是Windows NTFS磁盘属性：总容量显示651GB、已用532GB、剩余119GB。X:为开发环境使用的目录映射，属性显示底层磁盘整盘数据；不能据此认为项目占用532GB或ESP32有119GB内存。

本次只读统计：本机项目文件约175MiB（不含dev入口），SDK/工具/缓存/构建环境约8.66GiB；这两项是文件长度合计，不是操作系统分配大小，也不能代替其他软件的磁盘统计。当前剩余119GB足够继续目前的开发阶段，后续大规模视频或多套SDK再按实际占用管理。

| 资源 | 当前设备/环境 | 决策用途 |
| --- | --- | --- |
| 电脑磁盘剩余空间 | 截图显示119GB | 存源码、SDK、缓存、素材与构建产物 |
| 板载Flash | 32MB，已识别 | 存固件、字体、模型和动画；当前动画资源区仅10MiB |
| 外部PSRAM | 8MB，已识别 | 动画/图像等可外置运行数据；不能替代所有内部/DMA内存 |
| ESP32-S3内部SRAM | 芯片规格512KB | 驱动、任务、音频和部分运行数据；剩余堆随运行状态变化 |

8MB PSRAM与32MB Flash不能简单相加成“40MB可随意用的内存”，电脑剩余119GB也不能增加开发板运行资源。每个新功能需测内部堆、外部堆、最大空闲块、峰值、连续运行趋势及CPU/Wi-Fi影响。

芯片依据：https://www.espressif.com/sites/default/files/documentation/esp32-s3_datasheet_en.pdf 。本机32MB/8MB来自前期设备识别；本次未修改任何硬件或存储布局。

## 总体推进顺序

保留当前可用放大版 → 完成动画容量方案和动作库基础 → 做轻量UI原型 → 独立验证CSI → 再做语音、UI、动画、感知的联合资源与稳定性验收。

UI与CSI可以先做互不干扰的研究，但硬件整合分阶段进行。新增参考项目不代表马上整包移植，也不意味着所有功能已能同时运行。
