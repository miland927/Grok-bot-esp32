# 上传动画 → 独立资源更新 → 设备播放（USB 第一版）

## 目前可以做到什么

在设备当前资源上替换已有动作的 GIF，生成资源包，通过 USB 仅写入 `assets` 分区，校验后重启播放。这个过程不编译、也不写入应用，不修改开机程序、分区表、NVS 或 OTA 选择区。

设备仍使用自己的应用和菜单。新增菜单项、增加情绪触发规则尚未接入；工作台会阻止安装这类候选。当前也不是无线更新或按文件增量更新，每次传输整个资源包。

## 换电脑使用

在另一台电脑安装 Python 3.11+，获取包含本功能的分支，然后启动：

```powershell
git clone -b feature/usb-resource-update-20261023 https://github.com/miland927/chinchin-esp32.git
cd chinchin-esp32
python scripts/whale/manager.py
```

打开 http://127.0.0.1:8765 。该地址只服务正在运行程序的电脑，不能从另一台电脑直接访问前一台的工作台。

设备更新另外需要 esptool；本版实机验证使用 5.6.0。已安装到当前 Python 环境时工具路径可留空；否则填写包含 `esptool` 包的已有包目录。工具不会自动安装依赖。WebM 转换需要已有 FFmpeg/FFprobe。

源码和文档通过 Git 同步。每台电脑的设备配置、导入素材、草稿、备份、候选和日志在 `local-only/manager`，不会自动同步或上传 GitHub。完整备份包含私人配置，勿公开。

## 第一次连接

1. 将目标设备用 USB 接到这台电脑。
2. 进入“资源更新”，填写串口和目标设备 MAC，保存设备配置。MAC 是身份核验依据，不能只凭 COM3 判断设备。
3. 点“核验并完整备份”。设备会进入下载模式，读取完整 32MB Flash，再校验备份与分区布局，结束后重启。期间不能语音对话。
4. 面板切换到这台设备的真实资源基线；不会拿仓库里的旧资源覆盖设备。若有草稿，会拒绝同步而非丢弃草稿。

此入口仅支持已核验的 Waveshare ESP32-S3-Touch-AMOLED-2.06、32MB Flash、固定分区布局、未启用安全启动/Flash 加密的目标。它不是通用 ESP32 刷机工具。

## 添加与替换动画

1. 动作库 → 导入动作 → 选择文件。
2. 选择“替换某个已有动作”。例如替换待机动画，不会更改它的触发情绪。
3. 导入并预览；资源更新 → 生成候选包。
4. 核对变化后点“安装资源并重启”。程序再次核验设备身份、分区、应用代码、当前资源与备份，预留写入预算，再只更新独立资源。
5. 等待写入、资源校验、保护区校验与重启。检查屏幕显示、触摸、语音是否正常；串口校验成功不能代替这一步。

| 素材 | 限制 |
|---|---|
| GIF | 160×160，最多 600 帧，最长 15 秒；不自动缩放 |
| WebM | VP9，最长 15 秒；转换为 160×160、8fps、64 色 |
| 文件大小 | 单文件最多 20 MiB；最终资源包还须保留至少 10% 分区余量 |

目前使用文件选择器上传，没有专门的拖拽区。不支持任意尺寸 GIF、MP4、PNG 序列或 Lottie 直接导入。

若选“新增动作”或编辑名称/触发/冷却规则，可保存草稿、生成候选，但安装会拒绝，直到设备动态引擎接入。不要把按钮导入成功理解为已在设备生效。

## 看进度和日志

“任务与日志”显示任务状态、耗时和完成摘要；展开“运行日志末尾”会定期更新最多 48KB 的内容。编译输出可以在这里查看；USB 工具当前按阶段报告，具体 esptool 输出在本机设备会话目录，不显示虚假的总百分比。

- 统一任务完整日志：`local-only/manager/jobs/<任务ID>/full.log`
- 备份、串口阶段日志和写入结果：`local-only/manager/device-sessions/<会话ID>/`
- 当前设备操作结果：`local-only/manager/latest-device-operation.json`

固件编译需要已激活 ESP-IDF；Windows 中文工程路径在当前构建环境会被阻止，原因显示在构建按钮下。替换已有媒体无需点“构建固件”。

## 回退与异常

安装前有完整备份；“恢复更新前资源”只恢复备份里的整个资源分区，不回写旧 NVS 或应用。资源写入失败或被外部强制终止后也可用恢复入口，前提是目标身份、保护代码与备份仍匹配。

每个设备与候选组成稳定实验编号，默认共两次写入预算，通常对应一次安装和一次回退。达到预算会停止；不会自动反复刷写。新执行器的锁不约束旧私有脚本，请勿同时打开串口监视器或运行旧刷机脚本。

USB 资源任务不支持中途取消；必须保持供电，勿关服务。中途断电没有原子切换保证，可能需进入 USB 下载模式恢复。备份与回退是当前恢复措施，双槽原子更新尚未实现。

## 给下一位开发者

- 入口：`scripts/whale/device_resources.py`；管理 API：`manager.py`；基线/打包：`resource_manager.py`。
- `device-reference.json` 指向本机已验证资源，原 `whale/assets.bin` 保持原样。
- 更新前允许 NVS 随正常运行变化，但会捕获当次元数据并在写入后逐字节校验。应用/启动程序必须与备份匹配。
- 真实写入地址只允许 `0x1600000`，最大 `0xa00000`。不得添加合并固件、擦除全片、写 NVS 或应用的捷径。
- 主机模拟通过不代表设备播放通过；验收须分别记录传输校验、重启、视觉、触摸与语音。
- 本机确认了设备现有 13 动作资源，与交接哈希一致；13 动作/v7 完整源码仍缺失。不要用旧 10 动作代码重新编译覆盖该设备。
- 后续顺序：拿到最新源码 → 动态动作注册表/菜单与规则 → 无线资源通道 → 断电原子提交/回退 → 按文件增量 → 遥测与自动验收。
