# 鲸鱼娘小智：完整动画适配路线图

更新：2026-10-22T09:56:12+09:00（日本时间）

## 最终要达成什么

在现有 Waveshare ESP32-S3-Touch-AMOLED-2.06 上，做出尺寸合适、语音正常、动作丰富的鲸鱼娘：能够根据对话情绪、设备状态、触摸和空闲时间切换动作；动作切换自然，失败时能恢复，整套结果可备份、可复现。

完整素材范围以冻结版本后的清单为准，记为 N 个独立动画；仓库文档写的是 46+，不把文档宣传数量当成最终去重数量。素材来源：https://github.com/yanzwzz/dsh-whale-girl-pet 。

“全部适配”的完成条件：N/N 有素材、完成转换、确定播放方式和触发用途、在设备上逐个验证；每项保留结果记录。仅下载或仅在电脑上播放不算适配完成。没有合适情绪对应的生活动作，通过动作选择入口播放，不强行绑定情绪。

“全部同时装入一台设备”另有容量条件：只有 N/N 全部驻留、无需换包即可调用，才能使用这一说法。若最终只能分包，必须明确记录为“全库已适配、设备分包运行”，不能将其当作“全部同时装入”交付。

## 已经完成的基础

- 已通过第一轮：待机、思考、开心三种动画，用户确认显示、10 次触摸、5 轮语音正常；900 秒观察未发现重启或崩溃，用户确认断电重启正常。
- 通过验证的基线：`验证固件-v2-32MB寻址修复/`。原始 32MB Flash 备份位于 `设备备份/2026-10-22_030532_原固件1.8.5/`。
- 屏幕 410×502；当前动画画布 224×224。画布尺寸与人物实际占据的像素范围不同，放大要以人物看起来的大小衡量。
- 当前资源区 10,485,760 字节（10MiB），资源包 6,948,800 字节（约 6.63MiB）。其中三个 GIF 共 3,963,902 字节，字体约 2.49MiB，语音模型约 0.28MiB。

## 推进顺序和每阶段验收

| 阶段 | 要做什么 | 怎样算通过 |
| --- | --- | --- |
| P0 保留基线 | 固定当前通过验证的包、源码、配置、哈希和恢复说明；新修改另存版本。 | 能准确找到当前可用版和原始备份，历史文件不被覆盖。 |
| P1 优先放大角色 | 先用现有三种动画做尺寸调整，目标为人物可见宽高约增加 20%，保持比例和居中，调整点击区域。 | 用户确认“大一圈”合适；三种动作无裁切、无文字遮挡、触摸正常，语音正常。 |
| P2 全库清点 | 固定源提交，列出全部动画、尺寸、时长、透明度、文件大小、重复项、动作含义和来源记录。 | 得到可追踪的 N 项清单，每项有唯一编号；46+ 的实际数量和重复关系明确。 |
| P3 容量与播放实验 | 选待机、动作幅度大、运动复杂的代表素材，试裁透明边、缩短循环、调帧率和颜色、比较适合设备的编码。 | 得到肉眼认可的效果、实测体积和解码开销；计算全库预计体积，确定全量驻留或分包方案后再量产。 |
| P4 触发与切换规则 | 制作动作对应表；接入对话情绪、等待/回复、触摸、空闲及睡眠；设置打断和恢复规则。 | 每个动作都有明确用途和可测试入口；未知情绪有回退，交互不会阻塞语音，不会切换后卡住。 |
| P5 分批转换与适配 | 先做常用对话和触摸，再做空闲与睡眠，最后做生活动作；每批转换、打包、逐项预览和回归。 | 每一批的新增动画在设备上逐个通过；已通过的旧动画与语音仍正常。 |
| P6 全库与整机验收 | 完成 N/N 播放检查、场景测试、连续运行、压力触摸、断网恢复、断电重启与配置检查。 | 达到下文全部验收标准，问题清单中没有阻断项。 |
| P7 固定正式版本 | 保存镜像、资源、源码、清单、使用说明、恢复说明与验收记录。 | 能依据文档重复构建和安装；能明确说明当前装了哪些动作、如何触发、如何恢复。 |

## 第一优先级：先让大肥鱼大一圈

1. 使用当前三个已验证动作，不同时增加新动作，方便判断放大的实际影响。
2. 首选以当前人物可见宽高的 1.2 倍做第一版；若直接调整画布，224 的 1.2 倍约为 269 像素，可从约 268–272 的范围试起。最终以实机视觉为准，不能仅凭画布尺寸判断。
3. 先测人物在完整动画中的最大范围，保证跳跃、伸手、尾巴等不会被裁掉；保留时间、状态、文字区域。避免每个动作按各自边框独立拉满，导致人物忽大忽小。
4. 优先比较显示缩放与重新导出素材的效果和开销，不预先锁死实现方式；保持长宽比，透明背景正确，点击范围随人物一起调整。
5. 做现有尺寸与约 +20% 的对比，在设备上确认；若仍不合适，再小幅调整一次。
6. 本阶段验收：用户认可大小；三种动作各完整播放；10 次触摸命中；3 轮语音正常；运行 10 分钟无新异常；重启后尺寸保持。保存为独立的放大版本。

## 全库容量怎样决定

P3 需要先给出“质量、大小、帧率、运行开销”的实测表。顺序如下：

1. 去重复；裁掉无用透明边；保留原始素材不覆盖。
2. 循环动作找自然循环点，避免把十秒素材机械缩成不连贯片段；一次性动作保留必要的开始和结束。
3. 比较帧率、颜色和编码；以 P1 确认的人物可见大小为约束，不能为了塞满库又把人物缩回去。
4. 若当前 GIF 路径体积过大，评估其他编码与相应解码器。只有实测能在这台设备上正常播放且不影响音频，才采用；不假定 ESP32 可直接播放源 WebM。
5. 保留字体、语音模型和必要界面资源；不能通过破坏文字显示或语音功能来满足动画数量。
6. 按当前资源区估算，去掉现有三个 GIF 后，其余资源约 2.85MiB。若恰好 46 项全部驻留，平均每项大约只有 159KiB，且还需要预留余量。目标为包内至少保留 10% 空间，避免贴着上限交付。
7. 如果全量驻留仍不可行，先提交实测结论与备选方案：更换编码、常用包加可替换动作包，或评估重新分配 Flash。分包方案属于目标取舍；重新分区若涉及原厂程序或其他保留区域，属于额外修改，需要单独明确范围，不能静默执行。

在这道容量关口通过前，不把“46 个同时装入”承诺为已能实现；也不为了进度把分包结果记作全驻留完成。

## 动画怎样对应到行为

| 输入或场景 | 动画用途 | 约束 |
| --- | --- | --- |
| 服务端情绪标签 | 选视觉上贴切的表情动作。 | 标签表示服务端传来的表达状态，不等于识别到了用户声调或真实心情；不合适时用中性动作。 |
| 正在听、等待回答、正在回复 | 聆听/思考/工作类动作；具体按素材含义选择。 | 保持音频实时响应，不要求嘴型与语音逐字同步。 |
| 点击、双击、长按 | 点击回应、摸头、打开动作选择入口。 | 避免一次操作同时触发多个手势，明确打断与冷却规则。 |
| 空闲 | 呼吸、东张西望、伸懒腰等适度轮播。 | 不频繁随机切换，不抢占对话和触摸。 |
| 空闲入睡、唤醒 | 入睡过渡、睡眠循环、醒来过渡。 | 新对话应及时打断，不能为了播完睡眠动画延误语音。 |
| 特定生活动作 | 在设备的动作选择入口中主动播放；有合理事件时再自动触发。 | 吃饭、扫地等不硬套为悲伤、生气。时间触发需有正确时钟和去重规则。 |
| 没有对应项、资源加载失败 | 回到中性待机或安全占位。 | 不黑屏、不崩溃、不影响对话。 |

优先级初稿：关键设备提示 > 唤醒/对话响应 > 触摸反馈 > 空闲动作。动作表中分别写清“是否允许打断、是否循环、结束后去哪里、是否冷却”。最终以场景测试调整。

需要一个本地动作选择/预览入口，让每个动画都能主动调用并用于验收；不要求每个生活动作都由自然对话自动猜出来。更复杂的语义动作调用可在基本适配之后追加，不混入基础完成条件。

## 全部做完怎样验收

- 清单覆盖：N/N 都有源文件、转换文件、哈希、用途、触发入口及实机结果；循环动作至少连续 3 个循环，一次性动作至少完整播放 3 次。
- 显示：使用统一的人物比例和落地基线；全动作范围无不合理裁切、残影、透明底异常、文字遮挡或明显跳位。
- 情绪：本次纳入支持的每个标签均实际触发检查；未支持标签能回退，不能把“回退”写成对应动画已适配。
- 手势：单击、双击、长按各至少 10 次；不串触发；若最终只实现部分手势，必须明确削减范围，不能默认完成。
- 语音：至少 20 轮对话，覆盖快速连续说话、打断回复、对话中点击和从睡眠唤醒；声音与识别不因动画明显恶化。
- 长时间：连续运行至少 2 小时，包含动作轮播和实际对话；无崩溃、无非预期重启，无持续内存下降或明显卡顿。通过不等于已证明长期稳定。
- 恢复：断网再联网至少 3 次，完全断电再开机至少 3 次；原绑定和必要设置保留，仍能显示和对话。
- 容量与性能：包大小、运行内存、代表动作帧率和语音表现有实测记录；各资源包都保留余量。若使用分包，每个包分别验证，覆盖总库 N/N。
- 交付：当前安装清单、全量素材库、构建配置、镜像、工具、原始备份路径和恢复说明齐全。只有实际演练了恢复，才能声称“恢复流程已实测”。
