## 第二件事：真正增加第14动作

1. 在最新源码上把动作清单、菜单和触发规则改为数据驱动，补版本、容量和完整性校验。
2. 核对设备真实分区与资源，以13动作基线生成包含W002的新候选；复现无损优化时，用独立解码器确认每帧画面、时长和循环一致。
3. 审核`whale-actions.json`与固件实际支持的schema/ABI，只有兼容后才修改安装器对“新增菜单”的阻止条件。不能简单把`engine_upgrade_required_for_registry`改成false绕过去。
4. 首次动态引擎需构建并验证新应用；之后增加兼容动作只更新独立资源。

通过条件：长按菜单出现第14项、完整播放、到时恢复、语音可打断、断电重启仍保留、资源安装与回退均正常。分别记录构建、Flash校验和人工验收。

## 第三件事：接通原生说话表情

1. 采集真实对话的最小事件链：收到的原生情绪标签、状态切换、最终动作。确认服务端是否发标签，以及是否被neutral、等待状态或触摸优先级覆盖。
2. 复用原生`llm.emotion → SetEmotion → 动画`链路；不要用文本关键词猜测替代原生标签。
3. 补齐21种原生标签与未知标签回退。`whale/emotion-map.proposed.json`只是方案，部分为近似动作，尚未激活。
4. 资源中18个情绪别名指向待机是已发现的配置问题；尚不能证明这是当前v7完整故障根因。必须结合真实渲染路径确认。

通过条件：真实开心、生气、难过、惊讶事件能在说话中显示对应动作；结束恢复待机；触摸/手动菜单不阻塞语音；真实事件回放与实机均通过。
